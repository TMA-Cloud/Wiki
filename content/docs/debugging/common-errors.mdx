Frequently encountered errors and step-by-step diagnosis.

<Callout type="success" title="How to read this page">
  Each section lists the symptom, then a numbered checklist you can run
  top-to-bottom. Stop as soon as one step surfaces the cause — later steps
  assume earlier ones passed.
</Callout>

## Database connection errors

### Symptom: "Database connection failed" on startup

1. **Is Postgres actually up?**

   ```bash
   pg_isready -h "$DB_HOST" -p "${DB_PORT:-5432}"
   ```

   If this fails, start Postgres (Docker users: `docker compose up -d postgres`) before continuing.

2. **Are the credentials in `.env` the ones Postgres actually expects?**

   ```bash
   psql -h "$DB_HOST" -U "$DB_USER" -d "$DB_NAME"
   ```

   If this prompts for a password and fails, `DB_PASSWORD` is wrong.

3. **Is the backend pointing at the right host?** Inside Docker Compose, the host is the service name (e.g. `postgres`), not `localhost`.

4. **Firewall / network.** If Postgres runs on another machine, confirm the port is reachable: `nc -zv $DB_HOST 5432`.

## Encryption key errors

### Symptom: Backend or worker stops with "FILE_ENCRYPTION_KEY must be a random 32-byte key in production"

The key is a passphrase. Production accepts only a random 32-byte key in base64 or hex.

1. **Rotate to a random key.** Run `./rotate.sh key` on Docker, or `npm run rotate -- key` from `backend`. Both keep the passphrase as an older version so existing files still open. Replacing the key without rotating makes every stored file unreadable. See [Key Rotation](/docs/guides/operations/key-rotation).

### Symptom: "FILE_ENCRYPTION_KEY (key version N) does not match the key this deployment's data was encrypted with"

The configured key differs from the one recorded in `kek_checks`.

1. **Compare with your backup** of the key. A copy-paste error or a trailing character is the usual cause.
2. **Check the version prefixes.** In a keyring each line is `version:key`, and a key without a prefix is version 1.
3. **Check for both forms.** `FILE_ENCRYPTION_KEY` and `FILE_ENCRYPTION_KEY_FILE` must not both be set.
4. **The version is an older one?** A line kept for older data is wrong. Restore it from the key file backup.

### Symptom: "Stored data is encrypted under key version N, which FILE_ENCRYPTION_KEY does not contain"

A key line that file keys or the bucket secret still use was removed, or an older key file was restored.

1. **Restore the key file** from the backup taken after the last rotation.
2. **Check the version prefix** of each line against the versions in the message.

## Storage bucket errors

### Symptom: "Storage is not configured" (503 `STORAGE_NOT_CONFIGURED`)

No bucket is saved. The first user connects one in **Settings** → **Storage**. See [Storage Bucket](/docs/guides/admin/storage-bucket).

### Symptom: A connection check fails when saving the bucket

The message names the failed check.

1. **"Reach the bucket failed: Access denied"** — Check the access key ID, the secret, and the key's permissions. Some providers, including RustFS, answer a missing bucket with the same `403`.
2. **"Could not connect to the endpoint" or "did not respond in time"** — The backend container cannot reach the endpoint. Test from inside it, for example `docker compose exec app node -e "fetch('<endpoint>').then(r => console.log(r.status))"`. Any status code means the endpoint is reachable.
3. **"The bucket is in a different region"** — Set the bucket's region (Amazon S3).
4. **"Find existing files failed"** — The new bucket does not contain the files already stored. Copy the objects first.

## Redis connection errors

### Symptom: "Redis connection failed"

<Callout type="info">
  The app runs without Redis — caching and the SSE event stream degrade, but
  uploads, downloads and every other operation still work. Rate limiting is
  unaffected; the limiters keep their counters in the process, not in Redis.
</Callout>

1. **Is Redis running?** `redis-cli -h "$REDIS_HOST" -p "${REDIS_PORT:-6379}" ping` — should print `PONG`.
2. **Auth enabled?** If Redis requires a password, set `REDIS_PASSWORD` in `.env`.
3. **Right host in Docker?** Use the compose service name (`redis`), not `localhost`, from inside containers.

## Storage limit errors

### Symptom: "Storage limit exceeded"

1. **Check the user's quota in Settings → Storage.** If it's close to full, delete files or empty trash — trash counts toward quota.
2. **Check provider limits.** A full bucket quota or suspended provider account must be resolved with the storage provider.
3. **Admin override.** An admin can raise the limit for a specific user in **Settings → Registered Users**.

### Symptom: "This file is too large" on a single upload

The file exceeds the per-request max upload size (separate from storage quota).

1. **Admin → Settings → Storage → Max upload size.** Raise it if appropriate.
2. **Reverse proxy limits.** If you run nginx in front of the backend, `client_max_body_size` must also be raised — otherwise nginx rejects the request before it reaches the backend.
3. **Split the file** if you can't change the limits.

## Upload errors

### Symptom: "Upload failed" (generic)

1. **Check bucket availability** and provider quotas.
2. **Check bucket credentials and policies** — allow the backend to upload, read, list, and delete objects.
3. **Network stability** — retry once; transient drops cause this too.

See [Upload Issues](/docs/debugging/upload-issues) for upload-specific problems.

## Authentication errors

### Symptom: "Invalid credentials"

1. **Confirm email + password** — passwords are case-sensitive.
2. **Is MFA enabled?** If yes, the login flow needs a TOTP code; a missing code surfaces as this error.
3. **Rate limit.** After 25 attempts in 15 minutes from the same IP and email, further attempts are rejected until the window expires. Wait, or try from another network.

See [Auth Issues](/docs/debugging/auth-issues) for deeper auth troubleshooting.
